# Address Book REST API

Developed for SE4458 Assignment 2, Group 1: Address Book.

This backend application provides REST API endpoints to create, retrieve,
update, delete, search, sort, and favorite address book contacts.
No frontend is included. Swagger UI provides interactive API documentation.

## Links

- Source code: https://github.com/YasminMlgr/address-book-api
- Live Swagger UI: https://address-book-api-yasmin.onrender.com/swagger
- API base URL: https://address-book-api-yasmin.onrender.com/api/contacts

## Technologies

- C# and ASP.NET Core (.NET 10)
- Entity Framework Core InMemory
- Swashbuckle / Swagger UI
- Docker
- Render

## Design

The application uses ASP.NET Core controllers and dependency injection.

- `Controllers/`: HTTP endpoints and contact operations.
- `Models/`: Contact entity.
- `DTOs/`: Request models and supported sorting fields.
- `Data/`: Entity Framework Core database context.
- `Program.cs`: Service registration, routing, and Swagger configuration.
- `Dockerfile`: Multi-stage build and runtime configuration.

Each contact contains an automatically generated integer ID, first name,
last name, email, phone number, address, city, country, and favorite status.

Entity Framework Core's InMemory provider stores all contacts in application
memory, as required by the assignment.

## API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| GET | `/api/contacts` | List, search, sort, and filter contacts |
| GET | `/api/contacts/{id}` | Retrieve a contact by ID |
| POST | `/api/contacts` | Create a contact |
| PUT | `/api/contacts/{id}` | Update all editable contact fields |
| DELETE | `/api/contacts/{id}` | Delete a contact |
| PATCH | `/api/contacts/{id}/favorite` | Set favorite status |

### Search, Sorting, and Filtering

The list endpoint supports these query parameters:

| Parameter | Description |
|---|---|
| `search` | Case-insensitive partial matching across contact text fields |
| `sortBy` | `Id`, `FirstName`, `LastName`, or `City`; defaults to `Id` |
| `descending` | Set to `true` for descending order; defaults to `false` |
| `favoritesOnly` | Set to `true` to return only favorites; defaults to `false` |

Search covers first name, last name, email, phone number, address, city,
and country. An ID tie-breaker provides consistent ordering when sorting
values are equal.

Example:

```text
/api/contacts?search=deniz&sortBy=FirstName&descending=false&favoritesOnly=false
```

### Create or Update a Contact

Use this request body with POST or PUT:

```json
{
  "firstName": "Deniz",
  "lastName": "Yilmaz",
  "email": "deniz@example.com",
  "phoneNumber": "05551234567",
  "address": "Test Sokak No: 10",
  "city": "Izmir",
  "country": "Turkiye",
  "isFavorite": false
}
```

PUT requires the complete contact request body. The ID is supplied in
the URL and is not editable.

### Set Favorite Status

Use this request body with PATCH `/api/contacts/{id}/favorite`:

```json
{
  "isFavorite": true
}
```

Use `false` to remove the contact from favorites.

## Assumptions and Limitations

- Contacts are shared across API users; authentication is not implemented.
- IDs are generated by the database provider.
- Contact text values are trimmed before storage.
- Duplicate contacts are allowed.
- A search with no matches returns `200 OK` and an empty array.
- Requests for a missing contact return `404 Not Found`.
- Data is temporary and is lost when the application process restarts,
  including after a redeployment or a hosting restart.
- The API starts with an empty contact list.
- Test requests use fictional contact information.
- Render's free instance can become inactive, so the first request after
  inactivity may take longer.

## Run Locally

Install the .NET 10 SDK, open a terminal in the project directory, and run:

```bash
dotnet restore
dotnet run
```

Open the listening URL printed in the terminal and append `/swagger`.

The local application must be running to access its localhost URL.
The deployed Render application runs independently of the local computer.

## Run with Docker

With Docker installed and running:

```bash
docker build -t address-book-api .
docker run --rm -p 8080:8080 address-book-api
```

Open:

```text
http://localhost:8080/swagger
```

## Deployment

The application is deployed to Render as a Docker Web Service.

Configuration:

- Branch: `main`
- Runtime: Docker
- Root directory: repository root
- Compute: Free
- Environment variable: `PORT=8080`

The Dockerfile builds and publishes the application with the .NET SDK,
then runs it using the ASP.NET runtime image. The application listens
on `0.0.0.0:8080`.

Swagger is enabled in production. The root endpoint `/` redirects to
`/swagger`.

## Issues Encountered

### Localhost Connection Refused

The local Swagger URL was unavailable when the local application was
not running. The deployed Swagger URL was used to test the hosted API.

### Swagger "Failed to Fetch"

A request temporarily displayed "Failed to fetch" in Swagger.
The exact cause was not confirmed. Opening the endpoint directly
returned the updated contact and confirmed that the API was accessible.

### Temporary Data Reset

Previously created contacts were no longer present during later testing.
This is consistent with the temporary nature of the in-memory database
after an application restart. Test contacts were recreated to continue
testing.
